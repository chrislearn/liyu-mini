# 稳定性与故障恢复（1.0.46 / 服务端0.1.6，未发布源码）

## 版本与升级

先部署、核验服务端0.1.6，再安装客户端1.0.46。服务器镜像必须来自对应已通过检查的源码；当前本轮源码尚未发布，旧版本镜像不能代替。生产 Compose 必须显式设置 `LIYU_IMAGE`，本地构建步骤见服务端部署指南。升级前备份数据库和媒体；本地修改、API测试或 `/health` 成功都不能证明公网已升级。

新版读取熟人、心愿单、收/发礼盒、约定、通知时使用 `?limit=20&before=0`，按编号降序；商品目录使用升序 `cursor`。服务端根据JSON字节数缩小每页条数，返回 `next_cursor`，单项超限返回413。客户端校验完整分页、整数编号和游标前进，最多4096项；只有全部成功才替换列表。旧数组响应、异常游标或超限明确报错，原数据不会被误替换为空。列表不同于日期排序，新出现记录可通过再次读取获取；多页读取不保证数据库快照。

日期与有效期展示固定使用上海时间，心愿单业务日期及约定创建日期也不依赖数据库会话时区。金额按整数分转换，避免运行时 f32 数学函数丢失大金额、商品编号或游标精度。

## 未完成订单

真实账号在第一个订单写入前保存并读回 `purchase-recovery.json`。其中是版本、原幂等键、订单编号、报价、商品与收礼人、有效期和玩法配置；不含登录凭据或问题答案。存储由宿主按应用和账号隔离，演示不读写该记录。

重启／重新登录同一账号后主动「继续核验原订单」，问答礼盒需重新填写原答案。应用先读取原订单并核对金额、商品、收礼人；已测试支付的订单只继续配置／读回，不再支付。状态、金额或资料不一致时停止。结果未知时沿原幂等键和订单编号重试，不能重新创建另一份订单。

恢复文件损坏、格式无法核验或必需字段无效时，保留原文件并阻止新订单。已完成礼盒的恢复文件删除失败也保留当前恢复状态，不显示完成、不开放另一笔购买。存储写入／读回失败先修复应用存储，再从原订单继续；退出登录保留文件，清除应用数据会删除它。

遇到无法恢复的文件，请由运营者核对同一账号的原幂等键、订单编号、支付状态及礼盒配置，确认是否已有订单／礼盒、退款或取消结果后处理。不要直接删除文件后重买；不要将恢复文件、订单资料或宿主凭据上传公开问题页。自动修复不会猜测或取消服务端订单。

## 日历关联

`calendar-links.json` 保存所选日历句柄、事件编号、修订、原日期窗口和待核验状态。恢复时检查应用生成的JSON格式及必需字段；损坏或不可读时保留文件并停止原生写入。添加／更新事件之前必须保存并读回关联；写后再保存实际编号、回读核验。失败或结果未知不能当成成功，重试先查找已有事件。

重新选择日历或事件编号失效时，仅在原日期窗口查找唯一且内容相符的本应用事件；结果不完整、多条匹配或外部修改都会停止。原文件无法核验时先在系统日历核对已有事件，可继续导出 `.ics`，但手动重复导入也需自行检查。双方清除日期不会自动删除系统事件。权限及每次写入仍由宿主审阅。

## 检查与证据

从应用目录执行：

```sh
python3 scripts/check-local-demo.py
python3 scripts/check-net.py
python3 scripts/check-real-ai-flow.py
python3 scripts/check-ai-purchase.py
python3 scripts/check-host-calendar.py
python3 scripts/check-resilience.py
../OctoScript-App-Design-Flow/tools/octo check bundle
build/review-venv/bin/python scripts/check-bundle.py
```

最后一步需要按[验证文档](verification.md)安装固定Python依赖，可改用自己的验证虚拟环境。运行器按 `verification/standard-runtime.json` 固定，通过 `OCTO_HUB`、`OCTO_CARD_HOST` 选择已编译二进制。`check-net` 是宿主传输合成适配器，不发送真实账号凭据；AI、订单、日历测试也明确使用合成响应／写入适配器。恢复检查的应用文件与两次进程启动真实执行，存储故障使用显式注入。运行器检查不等于公网GUI、真实模型质量、系统日历或平台验收。

服务端从自己的目录运行 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings`，然后在自有一次性本地PostgreSQL集群设置 `DATABASE_URL`，执行 `python3 tests/run_ci.py`。运行器创建并清理每组专属数据库；不能连接不受自己控制的数据库。大列表套件同时改变数据库时区、给服务端设置失效出站代理，验证宿主内部请求仍正常。

详细范围和计数见[本轮验证](verification.md)。客户端macOS固定运行器CI新增作业尚待实际云端执行；真实账号双端GUI、官方RC6设备日历、生产部署及平台签名验收仍需各自记录。
