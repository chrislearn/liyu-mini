# LIYU → LIYU-MINI UI element audit (2026-09-29)

The native source of truth is `../OctoSense/apps/liyu/src/lib.rs`, `canvas.rs`, and `theme.rs`. The Splash mapping is `bundle/main.splash`. Measurements below come from the native widget declarations and `apply_shaping`, with a 412-point card-host window used for runtime checks. The native 1280-point desktop screen has a 208-point sidebar and right-hand aside. LIYU-MINI now offers a manually selected desktop mode with those three columns.

The phone and desktop shells now follow the native major columns, but this is not full native feature parity. Splash re-rendering currently resets the scroll position when a selector changes. The account editor, address editor, local contact import, voucher exchange, logistics, and desktop sidebar/aside are not reproduced. The server-backed gift and wishlist screens use server privacy projections instead of native local demo objects, so some sealed rows expose less information. Authentication now uses an OctoSense-owned sheet, whose modal framing differs from native `page_auth`; its fields and server flow match. The command screen is contained-app UI rather than a system AppCard action.

Earlier runtime checks used `card-host` at 412×775 and the live local server. A prior contact-gift form reached a server quote before contact entry was removed; the current gift form accepts friend IDs only. The broad-item wishlist form created test wishlist `2`, which was deleted immediately after verification. After the local social seed, the signed-in account showed 36 real server friends, 10 received and 10 sent gifts, and eight accepted contracts. The selected-recipient cards, individual X removal and “+ TA” picker were checked at 412×775. Two recipients received one combined quote and one paid test order, which generated two configured gifts. `octo check bundle` passed with the local test host declared.

Authentication checks used a newly registered local user through the host sheet over `https://liyu.localhost:8443`. Registration code delivery, account-specific `/me` and `/wallet` data, restart/session restoration, logout and server-side token revocation passed. A separate invalid-token session returned to the gate and removed the local token. The registration test used the server's explicit test-delivery channel; no fixed account was injected by Caddy.

Desktop mode was checked with a 1280×800 card-host viewport using live server data. The left navigation, middle catalog and right contextual cards rendered without overlap; the 412×775 phone viewport retained its bottom navigation and two-column product grid. The top-bar switch is explicit because this Splash app does not yet read its mounted viewport size.

Friend detail at 412×775 was checked with live seeded friendships. The profile groups open field-specific editors; a phone edit was saved through the host and reloaded from the server. A friend wishlist opened its detail with a per-item “送给TA” action. Sent gifts filtered by recipient ID; unrevealed incoming gifts are excluded from per-friend lists because the server hides their sender.
